# 連続再生

開発プランの第3段階を実装。既存の列挙・OP/ED整列の結果をPlaybackControllerに渡し、一覧から選んだURLを開始位置として末尾まで再生する。検証用の自動計測プレイヤーは独立して維持。

## 実装した挙動

- AVPlayerの項目を自然終了時に切り替える。リピートなし、末尾で終了表示。ギャップレス再生は保証しない。
- プレイリストと現在インデックスをPlaybackStateに保持。前へ／次へは各項目の先頭へ移動し、境界では何もしない。
- 初回選択は自動再生。一時停止中は前後移動・一覧選択でも停止意図を維持。終了後の再生ボタンは最終項目を再生し直す。
- ±10秒。巻き戻しは0秒で止める。早送りが末尾以上なら次項目へ移動し、次項目がなければ何もしない。
- 準備中と停止意図を分離。項目準備の待機は30秒でエラー扱い。
- 読み込み／再生失敗は次項目へ進む。連続3件、または末尾の失敗で停止して理由を表示。正常な再生時間進行で失敗回数をリセットする（iOS向け改善案を採用）。
- 切り替え時に監視・タイマーを解除し、世代番号で旧項目から届く非同期通知を無視する。
- 非アクティブ化時に一時停止。復帰時は手動再開。標準プレイヤー内の操作と意図が競合しないよう、映像はAVPlayerLayer、操作はコントローラー経由のボタンに統一。
- フォルダー切り替えでは再生を破棄してから旧フォルダーのアクセスを終了する。

## 後続工程

今回の自動再生テストはmacOSであり、iPhone／iPad実機での連続再生を確認した結果ではない。Files・iCloud・外部ストレージ、実素材の画角・音声・同期はdevice-validation.mdの未検証項目を維持する。

状態管理の追加実装は[state-management.md](state-management.md)を参照。通話割り込み、イヤホン切断、再生中の停滞、アクセス失効後の再選択を扱う。UI段階でホーム／再生画面、ジェスチャー、一時停止ツールバー、メディア情報、スリープ抑止を仕上げる。現段階は既存の検証画面から操作する。


## 開始直後のカクつき対策（2026-09-22）

ファイル選択後の画面表示を待つだけでは、実機での開始直後のカクつきは改善しなかった。
追加対策として、再生用アセットからのメディア情報取得を再生開始前に終え、AVPlayerの
`preroll(atRate:)` 完了後に再生する。準備中は「再生準備中」を表示し、固定時間の待機は設けない。
ファイルサイズの取得はメインスレッド外で行い、再生画面からのメタデータ読み込みは削除した。

準備中の一時停止・非アクティブ化は再生意図を解除する。項目切替・停止時には準備タスクと
prerollをキャンセルし、古い完了通知で再生や情報表示を戻さない。準備全体に既存の30秒タイムアウトを適用する。
ログの `PlaybackStartup` カテゴリーで情報取得完了、preroll開始・完了、2秒以上の再生停滞を確認できる。

回帰テスト: `sh scripts/test-playback-integration.sh validation/fixtures/09_h264.mp4`
（動画引数は任意。合成素材は `scripts/generate-fixtures.py` で生成する。）
実機USBでのカクつき改善は別途確認が必要で、ローカル素材のテスト成功は改善の実証とはしない。
