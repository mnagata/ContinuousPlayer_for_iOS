# Mac Catalyst検証記録

2026-09-24〜25、macOS 26.7／Xcode 27 SDK環境で確認。

## 実装

- 既存iOSターゲットのDebug／ReleaseでMac Catalystを有効化。
- Macのみ専用Bundle ID・サンドボックス・選択ファイルの読み書き／ブックマーク／ネットワーク送受信権限を設定。
- Macのみセキュリティスコープ付きブックマークを作成・復元。
- Macでも保存済みフォルダーと追加元のダイアログをiPhone／iPadと共有する。端末フォルダーの登録では標準ファイルダイアログでアクセス許可を取得し、保存済みフォルダーを開いた後はアプリ内一覧でサブフォルダーと開始ファイルを選ぶ。
- ローカル再生とDLNA再生の両方で、Macのみ非アクティブ時に再生を継続。バックグラウンドでは停止。
- iOS／tvOSの既存コード経路・ターゲットを保持。

## 確認済み

- Mac Catalyst Debug／Releaseビルド（arm64／x86_64、署名なし）。
- Mac Catalystのローカル開発用アドホック署名ビルドとMac上での起動。
- 署名済みアプリにMac用サンドボックス権限が含まれること。
- Mac上のホーム画面と標準ファイルダイアログの表示。「再生フォルダーを登録」と「OP / EDを選ぶ」が別の操作として表示されること。
- iOS Simulator／tvOS SimulatorのDebugビルド。
- `scripts/test-enumeration.sh`：列挙、フォルダー移動、権限範囲、OP／ED順。
- `scripts/test-playback.sh`：再生状態遷移。
- `scripts/test-playback-integration.sh`：macOS上での共通AVFoundation再生処理、フォルダー権限保存・復元。
- `scripts/test-dlna.sh`：ローカル模擬サーバーでのDLNA通信、HTTP連続再生、シーク、エラー処理。

## 2026-09-25 ファイル選択後にホームへ戻る不具合

読み取り専用の署名設定では、標準ファイルダイアログで動画を選んでも `documentPickerWasCancelled` が呼ばれ、選択URLがアプリへ届かなかった。同じコードで選択ファイルの権限を `read-write` にすると `didPickDocumentsAt` が届くことを確認した。読み書き権限は標準ダイアログからの受け渡しに必要であり、アプリはメディアを読み取るだけで変更しない。保存済みブックマークは読み取り専用のまま。

Macの選択処理は `CatalystDocumentPicker` に分離し、ダイアログを閉じた後に完了通知を渡して、再生画面やフォルダー選択の案内と競合しないようにした。選択／キャンセル／再生準備の診断は `FileSelection` カテゴリに記録する。

実機の標準ダイアログ操作で以下を確認した。

- ファイルを選ぶと、未許可フォルダーの場合はフォルダー選択の案内が表示される。
- そのフォルダーを選ぶと動画の再生が始まり、実際の映像が表示される。
- Spaceキーで一時停止し、右矢印で次の動画に移動できる。
- アプリを終了・再起動した後は、同じフォルダー内のファイルを選ぶだけで再生が始まる。追加のフォルダー選択は不要。
- iOS／tvOS Simulatorのビルドと、既存のAVFoundation・アクセス範囲の統合テストが成功する。

## 2026-09-28 フォルダーダイアログの共通化

Mac Catalystでも、保存済み端末フォルダーを選んだ後にiPhone／iPadと同じ `MediaFileBrowser` を開くよう変更した。新規フォルダーのアクセス許可には引き続きmacOSの標準ダイアログを使用する。上記2026-09-25のファイル選択に関する記録は変更前の動作を示す。Mac上で保存済みフォルダー、追加元の二択、サブフォルダーとファイルの一覧表示を確認した。ファイル選択後の再生は未確認。

## 2026-09-29 再生画面上のファイル選択

無音ファイルと単色の検証用動画で再生画面を一時停止し、フォルダーボタンからアプリ内一覧が映像の上に重なることをMac Catalyst上で確認した。「キャンセル」後は同じ動画の一時停止画面に戻り、再生ボタンと映像フレームが残った。検証用アプリとファイルは確認後に片付けた。DLNA再生画面の同じ操作は実サーバーで未確認。

## 2026-09-25 Escで閉じた後も音声が続く不具合

ローカル再生画面のボタンを経由しないシステムのdismissでは、再生終了処理が呼ばれていなかった。`ContentView.presentationDidDismiss()` で再生中のURLを記録し、AVPlayerの停止・アイテム解放・非同期準備のキャンセルを実行するよう修正した。メディア情報シートを閉じる処理は変更していない。

- Mac実機で再生中にEscを押し、ホームへ戻ることを確認。
- `PlaybackLifecycle` ログで `rate=0.000000, hasItem=false` を確認。
- 統合テストに、再生中の終了と準備途中の終了後に再生が復活しない検証を追加し成功。
- Catalyst／iOS SimulatorのDebugビルドが成功。

## 残る確認事項

上記の共通処理テストはmacOS向けSwift実行ファイルであり、Catalystのサンドボックス内でのUI試験とは異なります。以下は引き続き未確認です。

- USB取り外し時の動作。
- Mac実機上でのNAS検索・接続・ローカルネットワーク許可。
- 音声の聴取、すべてのキーボード操作、全画面とウインドウサイズ変更。
- アプリ切り替え中の再生継続、音声デバイス切断時の停止。
- Intel Mac実機、配布署名・公証・Mac App Store提出。

## 再確認の手順

1. `./script/build_and_run.sh --verify` で起動。
2. 「OP / EDを選ぶ」→「フォルダーを追加」→「端末のフォルダー」からフォルダーを登録し、登録だけでは再生が始まらないことを確認。保存済み一覧からそのフォルダーを開き、アプリ内一覧でサブフォルダーと開始ファイルを選び、連続再生を確認。キャンセル時は再生を開始しないことも確認。
3. Space、左右矢印、Shift＋左右矢印、上下矢印、I／Escを確認。
4. 他アプリへ切り替えて再生継続を確認し、ホームへ戻ってからアプリを終了・再起動。
5. 許可済みフォルダーを再選択せずに開けることを確認。
6. NASのアドレス指定接続とSSDP検索から同じ再生操作を確認。
