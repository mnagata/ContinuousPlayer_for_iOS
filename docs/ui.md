# UI実装

開発プランのUI工程として、通常起動を検証画面からホームへ切り替えた。

## 画面と操作

- アクセス許可: ホームの「USBストレージへのアクセスを許可」でUSB内のフォルダーをシステムピッカーで選び、セキュリティスコープを含むブックマークをアプリのUserDefaultsへ保存する。許可完了後はホームに戻り、保存したフォルダー名を表示する。ファイル一覧の作成や再生は行わない。
- 復元: 次回起動時に保存ブックマークを解決し、startAccessingSecurityScopedResourceでアクセスを再開する。解決後のURLからブックマークを更新するため、古くなったブックマークも更新される。取り外し・失効時は再許可を案内し、勝手に許可画面へ進まない。
- ファイル選択: 「OP / EDを選ぶ」は許可済みフォルダーの読み取りを確認してシステムのファイル選択だけを開く。選んだファイルの親フォルダーをソートし、そのファイルから連続再生する。未許可・許可範囲外の場合はホームの許可ボタンを案内する。
- キャンセル: 再生を開始せず元の画面に留まる。選択結果と終了通知の両方が揃ってから処理する。独自一覧はDebugの素材検証起動のみで使用する。
- 再生: 左右1/3のシングル／ダブルタップで±10秒、中央で再生／停止。水平スワイプで前後移動。ジェスチャーは映像領域のみで処理する。
- キーボード: 再生画面で修飾キーなしの←は前のファイル、→は次のファイル、Spaceは一時停止／再生。↑／↓はアプリ内の再生音量を5ポイントずつ増減（0〜100%、初期値100%）し、操作時に1.5秒間表示。本体音量との組み合わせで出力される。曲を切り替えても音量を維持。Shift＋←／→は10秒戻す／進める（タップと同じシーク処理）。Iでメディア情報を開き、情報画面ではIまたはEscで閉じるため、Escキーがないキーボードにも対応。操作ボタンが非表示でも有効。前後移動は現在の再生／一時停止状態を維持し、先頭での←・末尾での→は何もしない。メディア情報表示中、非アクティブ時、フォルダーの再選択が必要な状態では無効。
- 一時停止: PlaybackControllerの再生意図を使用。準備・バッファリングだけではツールバーを出さない。ホーム、フォルダー選択、情報、再生のボタンを表示。前後移動と±10秒は下部ボタンでも操作可能。
- 終了・エラー・アクセス失効: 操作と理由を表示。ホームへ戻ると再生項目を解放。フォルダー選択ボタンは再生を終了し、シートの終了後にシステムピッカーを開く。
- 情報: ファイル名・サイズ、取得可能な映像コーデック／解像度／fps、音声コーデック／サンプルレート／チャンネル数を非同期取得。項目切替後に古い取得結果を反映しない。
- 音声出力: AVAudioSessionの現在の出力先・実サンプルレートを表示し、経路変更時に更新。詳細には出力チャンネル数も表示。ビットパーフェクトとは表示しない。
- サイズ対応: GeometryReaderで表示領域の縦横を判定。縦では情報、横では映像を優先。情報・ホームをスクロール可能にし、セーフエリア内に操作を配置。
- スリープ: 再生画面がアクティブな間だけ抑止。非アクティブ・画面終了で解除。
- アクセシビリティ: 操作ラベル、44pt以上のボタン、無効表示、VoiceOver有効時の常時操作表示。
- アイコン／起動画面: Androidの前景パスをCore Graphicsへ移植。起動画面は同じロゴと濃紺背景。生成元は scripts/generate-brand-assets.swift。

フォルダーブックマークは既存のキーを継承。MediaLibraryが通常画面のフォルダーアクセスを所有し、検証のログ・自動再生と分離した。`--validate-fixtures` / `--validate-real-samples`（または `--validate-ui`）で従来の検証画面を利用できる。

## ファイル選択フローの変更（2026-09-20）

iOSではUIDocumentPickerViewControllerを利用する。アクセス権のない初回はフォルダー選択だけで許可と先頭再生を行い、許可済みの場合はファイル選択で開始位置を指定できる。保存したブックマークの存在だけでなく、復元したフォルダーを読み込めるかで分岐する。

ソート・列挙テストと再生統合テスト、iOS Simulator向けビルドで検証。上記の過去の実機結果は変更前のもの。更新したFiles選択・復元UIテストの実機再実行は未実施。

### 再生後のフォルダー変更の修正

フォルダー選択と再生画面を単一のfullScreenCoverで管理し、選択URLの通知と画面終了の通知が両方揃ってから一度だけ読み込み・再生へ進める。通知の順序に依存して選択結果を取り逃し、ホームに留まる経路を解消した。すでに保持しているフォルダーアクセスは再選択前に復元し直さない。

iPhone 18 Pro / iOS 27シミュレーターで修正前の「別フォルダー選択後にホームのまま」を再現し、修正後は新しいフォルダーの先頭曲の表示・再生状態までUIテストで確認。再生統合テストでも、フォルダー切り替え後に再生時間が進むことを確認。実機のUSB・iCloudでの再検証は未実施。

最終確認: iPhone 18 Proシミュレーターで別フォルダー再生とキャンセルのUIテスト2件が成功。全画面ピッカーには明示的なキャンセルボタンを配置した。

### 許可済みフォルダーでの開始ファイル選択

現在のフォルダーが読み取れる場合はファイル選択を利用する。保存済みフォルダーより現在保持しているフォルダーを優先し、ブックマークがあるだけでは許可済みと判断しない。単一の画面表示管理と、選択通知・終了通知の両方を待つ処理は維持した。

検証: 許可済みの現在フォルダーからのファイル選択・再生と、別フォルダーへの切り替えをiPhone 18 ProシミュレーターのUIテスト2件で確認。アクセス判定、ソート後の選択位置、フォルダー変更後の実再生を統合テストでも確認。実機検証は未実施。

### アクセス不可からフォルダー許可へ切り替える経路

システムピッカーに選択種別のidentityを設定し、ファイル用からフォルダー用へ切り替わる際は作り直す。Coordinatorの結果ハンドラーも更新し、以前の選択種別を保持しないようにした。

`testGrantFolderAfterSelectingFileOutsideCurrentFolder`で、現在の許可範囲外のファイル選択→フォルダー許可→ソート済み先頭の再生をiPhone 18 Proシミュレーターで確認。統合テストでは読み取り不能フォルダーからの復帰、および許可外ファイル選択後のフォルダー再取得の両方で再生時間が進むことを確認。実機の外部ストレージでの再確認は未実施。

### ファイルタップの選択条件

ファイル選択の許可型を拡張子別UTIからpublic.dataへ変更。File Providerが汎用データとして返すメディアも選択できるようにし、対応拡張子は選択結果を受け取った後にMediaLibraryで検証する。非対応形式は理由を表示し、フォルダー許可へは進めない。フォルダー選択中は「フォルダーを開いて右上の開く」、ファイル選択中は「ファイルをタップ」の案内を表示する。

変更前のローカルWAVタップ再生はシミュレーターで成功しており、報告された環境での無反応は未再現。種別情報の差による選択不能への対策として実装した。

確認結果: 変更後のローカルWAVのタップ再生と、許可範囲外ファイルからフォルダー許可を経て再生するUIテスト2件が成功。非対応拡張子で理由を表示する統合テストも成功。報告されたファイル・保存先での再現確認は未完了。

### アクセス許可と再生選択の分離（2026-09-21）

ホームの2ボタンに機能を分離。iOSのドキュメントピッカーから返されたsecurity-scoped URLに対し、アクセス開始中にminimalBookmarkでデータ化して保存する。iOSではwithSecurityScopeオプションは利用不可であり、暗黙のsecurity scopeを保持する標準のブックマーク方式を使用する。保存キーは従来のものを引き継ぐ。

統合テストで許可時に再生しないこと、保存、別インスタンスでの復元後の選択再生、破損データの失敗処理を確認。

検証結果: シミュレーターで許可保存後に再生しないことと、終了・再起動後のファイル選択再生を確認。接続中iPadでもUSBフォルダーの許可保存→アプリ終了・再起動→MP4選択再生のUIテストが成功。最新版を実機へインストール済み。

### 再生停止後のカレントディレクトリ（2026-09-21）

アクセス許可のルートfolderURLと、再生ファイルの親currentDirectoryURLを分離。ファイルダイアログはcurrentDirectoryURLを初期位置に使用する。再選択前の読み取り確認では許可ルートを開き直さず、現在のディレクトリのアクセスを確認するため、上位フォルダーへの巻き戻りと表示名のリセットが起きない。URLにはディレクトリのヒントを付ける。新たなフォルダー許可・起動時のブックマーク復元時は、その許可フォルダーを初期位置に設定する。

統合テストで許可ルート配下のサブフォルダー再生後、停止と選択準備を経ても現在のディレクトリを維持し、許可ルートを変更しないことを確認。

検証結果: サブフォルダーでの再生→停止→ファイル再選択のUIテストはiPhoneシミュレーターで成功。実機向けのビルド・インストールは完了したが、実機UIテストはSpringBoardのアニメーション待機で停滞したため中止し、この変更のUSB実機再確認は未完了。

### 横向き向けのファイル選択（試用切り替え）

許可後の「OP / EDを選ぶ」は、検索窓なしの全画面一覧を標準とする。
上部はキャンセル・現在のフォルダー名・上のフォルダーへ戻るボタンの1段にまとめる。
ファイル名は拡張子付きで最大2行、フォルダーを先に表示し、メディアは既存のOP / ED順に並べる。
許可したフォルダー内のサブフォルダーへ移動できる。隠しファイルと許可範囲外へのリンクは表示しない。
初回のアクセス許可は従来どおりiOS標準ダイアログを使う。

戻す場合は、ホーム画面の「標準ファイルダイアログを使う」をオンにする。
次回のファイル選択から従来の画面になり、再起動後も設定を保持する（UserDefaults: `useSystemFilePicker`）。
オフにすると独自一覧に戻る。フォルダーのアクセス許可を取り直す必要はない。

実機確認: iPhone 16を横向きにして、一覧の表示行数・長い名前・サブフォルダー移動・
キャンセル・選択後のプレイヤー表示・再生画面からの再選択を確認する。
その後スイッチをオンにして、従来のダイアログへ戻ることも確認する。

独自一覧で「上のフォルダー」を押すと、親階層の読み込み後に、出てきたフォルダーの行を中央に表示する。
再生後に一覧を開いて親へ戻る場合も、再生ファイルの入っていたフォルダーを見つけやすくする。

独自一覧のフォルダー名が「共通名 + 西暦4桁 + 季節」で終わる場合、共通名ごとに年の昇順、冬→春→夏→秋の順に並べる（例: アニメOPED 2025冬）。年の後の「年」や空白も許容する。その他のフォルダーは従来の名前順を保つ。

再生画面から独自一覧を開くと、再生状態をリセットする前に保持したファイルの行を中央付近へスクロールする。一時停止中も同様。対象ファイルがなくなっている場合は先頭表示とし、親階層へ戻る操作では従来どおり出てきたフォルダーの行を優先する。
