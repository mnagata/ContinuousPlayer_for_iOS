# 列挙と整列

開発プランの「列挙と整列」を実装。画面から `MediaScanner` と `PlaylistSorter` を分離した。

- フォルダー直下の通常ファイルのみを非同期で列挙。NSFileCoordinatorを利用し、アクセス権限は呼び出し元が再生終了まで保持する。
- mp4/m4v/mp3/flac/m4a/aac/wav/ogg/opusを大文字小文字を区別せず採用。`._`ファイルを除外し、一般の隠しファイルは含める。サブフォルダーは探索しない。
- 現在のロケールの名前順（大文字小文字を区別せず、数値の自然順オプションなし）を基準にする。
- 最後の拡張子を取り除き、前後をトリムして `^(.+?)\s+(OP|ED)([0-9]*)$` に一致する名前を抽出。作品名をトリム・小文字化してグループ化する。
- 同じ作品の該当スロットだけを番号→OP/EDの順で入れ替える。非該当ファイルの位置は維持する。番号省略・Int32範囲外はAndroidと同じ1、0も有効。同順位は元の名前順、比較が等しければ入力順を保持する。
- フォルダー選択ではアクセス許可を保持し、直下を列挙・ソートして先頭から再生する。許可済みならシステムで開始ファイルを選択し、親フォルダー直下を列挙・ソートして選択位置から再生する。保存済み許可の復元時はフォルダーを読み込めるか確認し、再生は開始しない。独自一覧はDebugの素材検証でのみ使用する。

## 検証

`sh scripts/test-enumeration.sh` でFoundationベースのテストを実行する。番号・カテゴリ順、非該当位置保持、同順位、別作品、拡張子と大文字小文字、番号の境界、隠しファイル、サブフォルダー除外、選択URL保持、読み取り失敗を検証する。テストは一時ディレクトリだけを使用する。制限された実行環境ではNSFileCoordinatorのサービスアクセス許可が必要。
