# 状態管理

開発プランの「連続再生 → 状態管理 → UI」の状態管理を実装した。再生履歴の永続復元と完成版UIは後続工程。

## iOS版の挙動

- 再生意図（PlaybackState.wantsToPlay）、準備中、バッファリング、終了、アクセス失効を分離。showsPauseControlsは停止意図を基準とし、再生意図がある準備・バッファリング中には一時停止ツールバーを出さない。UI工程で利用する。
- 非アクティブ化・通話などの割り込み・音声出力機器切断で停止。復帰や割り込み終了の通知では自動再開しない。再生ボタンで手動再開する。
- 非アクティブ中と割り込み中は、再生ボタンや明示的な自動再生指定でも再生しない。停止中の項目切替は停止意図を維持する。
- AVAudioSessionを再生用として有効化。有効化失敗は停止して理由を表示。音声サービスのリセット時はAVPlayerを再生成し、手動再開時に現在項目の先頭から読み直す。
- 準備待ちは既存の30秒制限。準備完了後は単調時計で進行を監視し、2秒間進まなければバッファリング表示、30秒で既存の失敗処理へ渡す。停止時間は停滞に含めず、再開・項目切替・進行時に基準を更新する。
- 権限拒否やデバイス不在を示すCocoa/POSIXエラー（下位エラーを含む）は、スキップせず再生を破棄し、フォルダー再選択を案内する。再選択・列挙成功で解除し、選択した項目から再生する。以前の再生位置は復元しない。
- フォルダーブックマークの復元・列挙失敗でも再生を停止する。通常のファイル破損・ファイル単体の不存在は、従来の連続3失敗／末尾停止を維持する。
- 外部ストレージ切断時に返されるエラーはプロバイダー依存。明確なアクセスエラー以外は通常の失敗／停滞処理となる。バッファ済み部分が再生できている間の切断を即時検出する保証はない。
- 項目監視とアプリ存続中の音声通知監視を分離し、項目世代番号で古い通知を無視する。破棄時は監視・タイマーを解除する。

## 検証（2026-09-19）

- `sh scripts/test-playback.sh`: 既存の純粋状態テスト成功。
- `sh scripts/test-playback-integration.sh`: macOS上のAVFoundationによる連続再生・シーク・旧項目通知・連続失敗に加え、非アクティブ／割り込み中の再開抑止、復帰後の停止維持、機器切断後の停止、アクセスエラー通知と再選択後の解除、停止中の停滞除外を確認。
- 停滞判定は実際の時計監視と同じ判定関数へ経過時間を渡し、バッファリング表示と30秒の失敗遷移を検証。実ネットワークを30秒間停止させた試験ではない。
- iPhoneOS Debugの署名なしビルド成功。既存の映像検証API2件と今回利用した割り込みAPIにiOS 27非推奨警告あり。

iOS固有のシステム通知の実配送、通話、イヤホン／USB取り外し、iCloud停滞、アクセス失効後のFiles再選択は実機未検証。手順は[device-validation.md](device-validation.md)を参照。macOSで状態遷移が通ることを実機動作の保証とはしない。

## 共通仕様・段階1（2026年10月28日）

- シーン所有の `PlaybackSessionCoordinator` が再生コントローラーを保持し、ローカルライブラリーとDLNAブラウザーへ注入する。tvOSでも一覧表示でプレイヤーを閉じない。
- `beginPresentation`／`endPresentation` で一覧・情報の停止と復元を共通化する。表示中は同じ項目・キュー・秒数を維持し、トランスポート操作と自然終了による進行を抑止する。
- 表示開始時のセッション世代・項目世代・割り込み世代を検証する。背景化、保護データ利用不可、音声割り込み、出力切断、Macの非表示・スリープ等が一度でもあれば自動再開しない。
- 明示的なファイル選択は同じファイルも0秒から再生する。Viewの初回表示で再開せず、選択確定で再生意図を設定する。準備失敗は選択先に留まる。
- iPadは表示中の非アクティブ状態を許可し、背景化で停止する。Macの複数の停止要因は集合で保持し、一つの解除で他の停止要因を無効にしない。
- ホーム・シーン切断・アプリ終了で、項目と準備および復元トークンを無効化する。ローカル列挙の遅い完了も終了後のセッションを再開しない。
- `sh scripts/test-playback-session.sh` は長尺素材で30秒の復元・割り込み・入れ子表示・準備／終了通知との競合・選択エラー・ローカル選択を検証する。先に共通仕様用素材を生成する。

古い本文の「非アクティブ化時に停止」は、iPhone／tvOSと、iPad／Macの停止条件を上記のとおり区別する。通常の再生中エラーの自動スキップ廃止は段階3の対象。

## 共通仕様・段階2（2026年10月29日）

- `PlayerSceneModel` が再生面・ホーム・一時表示トークンを所有し、`FileSelectionCoordinator` がホーム／再生からの選択・追加の画面状態を所有する。`MediaLibrary` は確定したローカル再生の権限だけを更新する。
- 登録ルートの親は保存済み一覧。DLNAの追加時だけサーバーの祖先を閲覧する。親移動・選択全体キャンセル・ホームを分ける。
- 登録は追加／更新と解除を分離し、解除は同じ確認を通す。解除で再生中のアクセス権を解放しない。閲覧用の権限は別に保持し、ファイル確定時に受け渡す。
- 一覧取得の要求世代で遅延応答を無効化する。取得中は旧タイトル・行を残し、0.5秒後に読み込みを重ねる。旧行決定・登録・追加を止め、取得中の戻るは選択全体をキャンセルする。
- 行・フォルダーの選択はローカルのパス、またはDLNAのサーバーIDとオブジェクトIDで保持する。再生中の現在行は選択時のURLだけに依存しない。
- ホーム・シーン切断・アプリ終了で選択要求と準備も終了する。ファイル確定では黒い再生面を先に用意し、列挙中にホームを露出しない。

詳しい接続と検証範囲は [段階2の記録](stage2-selection-2026-10-29.md) を参照。
